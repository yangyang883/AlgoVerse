# 错误分类表（D4 / 错误分析口径）

- 版本：v0.1　｜　维护：组员 5　｜　适用：全部评测题与失败样例
- 分类依据：项目书 9.3「失败样例及错误类别（检索/意图/字段/工具路由/执行/解释）」
- 原则：**一题可有多条错误记录，但主因只能有一个**；主因用于分母统计，副因只做定性描述。

## 1. 主类与子码

| 主类 | 子码 | 触发条件 | 判定方法 | 主责 |
|---|---|---|---|---|
| 检索 `R` | `R-01` 无召回 | RAG 返回空或 Top-k 全部不相关 | 人工看检索结果，判是否含支撑该结论的知识单元 | 组员1 |
| | `R-02` 错误引用 | 引用了不存在或与结论无关的 source_id | 用 `source_id` 回查知识库是否存在、是否支持该结论 | 组员1 |
| | `R-03` 引用缺失 | 知识题要求引用但回答无出处 | 检查响应是否含 source_id / 链接 | 组员1 |
| 意图 `I` | `I-01` 误分类 | 知识问答被当成实验配置，或反之 | 对比 `intent` 字段与题目期望模式 | 组员1 |
| | `I-02` 追问理解错误 | 多轮中把"改成 X"理解为新增/重置 | 对比前后两轮 config 差异 | 组员1 |
| 字段 `F` | `F-01` 缺字段 | config 缺少 `required_fields` 中的路径 | 路径存在性检查 | 组员3 |
| | `F-02` 值错误 | 字段存在但值与期望不符 | `field_values` 逐项比对 | 组员3 |
| | `F-03` 非法枚举 | 枚举值不在冻结清单内 | Schema 校验 | 组员3 |
| | `F-04` 未知字段 | 出现契约外字段 | `forbidden_fields` + Schema 校验 | 组员3 |
| | `F-05` 超限未拦截 | size / 轨迹步数超上限仍执行 | 对照上限规则 | 组员2 |
| 工具路由 `T` | `T-01` 路由错误 | 该调 run 却调 chat，或跳过 validate | 看工具调用序列 | 组员3 |
| | `T-02` 未注册算法 | 对未注册算法伪称可执行 | 对照 `/algorithms` 能力表 | 组员2 |
| | `T-03` 越权执行 | 绕过白名单执行任意代码 | 审查执行器入口 | 组员2 |
| 执行 `E` | `E-01` 执行异常 | 抛异常、非零退出 | 服务端日志 | 组员2 |
| | `E-02` 结果校验失败 | 输出非有序 / 非多重集重排 | 验证器 `validation` 字段 | 组员2 |
| | `E-03` 超时/资源超限 | 触发超时或内存/步数上限 | 日志与状态码 | 组员3 |
| | `E-04` 截断未标记 | 轨迹超限但 `trace_truncated` 未置 true | 对比轨迹长度与标志 | 组员2 |
| 解释 `X` | `X-01` 编造统计 | 解释中的数字与 `metrics` 不一致 | 逐项数字比对 | 组员1 |
| | `X-02` 未执行声称执行 | 无 `run_id` 却描述执行过程 | 检查响应是否引用真实 run_id | 组员1 |
| | `X-03` 解释与轨迹冲突 | 描述的第 k 步与 `trace` 不符 | 轨迹逐事件核对 | 组员1 |

## 2. 记录字段（每条失败记录必填）

| 字段 | 说明 |
|---|---|
| `case_id` | 题号 |
| `run_id` | 本次运行标识，可回查原始响应 |
| `primary_code` | 主因，如 `F-02` |
| `secondary_codes` | 副因列表，可空 |
| `evidence` | 关键证据：响应片段 / 字段路径 / trace 步号 |
| `reviewer` | 判定人 |
| `judged_at` | 判定日期 |
| `fix_owner` | 归因模块负责人 |
| `status` | `open / fixed / wontfix` |

## 3. 统计口径

1. **分母**：该类别的实际完成题数（不含未跑、未评分），不是计划题数。
2. 一题只计一次主因；`primary_code` 空缺视为未完成判定，不计入分子也不计入分母。
3. 网络/服务不可用导致的失败记 `E-03`，并在报告中单列"环境失败"，**不混入模型能力结论**。
4. 同一失败若跨模块，按"最近可修复点"归因：配置错算 `F`，配置对但执行错算 `E`，执行对但描述错算 `X`。

## 4. 禁止事项

- 不使用"模型能力不足"这类无法复现的笼统分类。
- 不把 P1 未支持的功能（如 Dijkstra 执行）记为失败，单独标 `T-02 not_supported`。
- 不删除失败样例；修复后在 `status` 改 `fixed`，原始记录保留。

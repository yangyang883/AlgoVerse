## 六、给组员 3 的日志字段需求

每次请求至少落这些字段，否则失败无法归因（分类码见 `error-taxonomy.md`）：

| 字段 | 用途 |
|---|---|
| `request_id` | 全链路串联，响应信封已要求 |
| `session_id` / `case_id`（评测注入） | 定位多轮上下文 |
| `endpoint` / `http_status` / `latency_ms` | 区分超时与业务错 |
| `intent` 判定结果、`tools_called[]` | 判 `I-01`、`T-01` |
| `config`（解析后）与 `schema_error` | 判 `F-01~F-04` |
| `run_id` / `metrics` / `validation` / `trace_truncated` | 判 `E-02`、`E-04` |
| `model_id` / `temperature` / `prompt_version` / `kb_version` | 报告可复现 |
| `error_code` + 原始报文 | 判 `E-01`、`E-03` |

已由组员 3 的最新交接确认：`request_id` 在统一信封与 `X-Request-ID` 中；`run_id` 存 SQLite `experiments` 表；`/experiments/compare` 请求体为 `{"run_ids":["id-1","id-2"]}`。当前服务端没有独立的 `schema_error`、`intent`、`tools_called` 字段，Schema 错误路径从 `error.details.errors[].loc` 读取。

## 七、给组员 4 的结果页数据样例

研究评价页只需要读 `results/raw/<run_id>/summary.json`，建议展示：

```
run_id, mode(real/mock), dataset.version, dataset.case_count,
ok_cases, failed_cases,
by_category.{category}.{total|ok|failed},
by_error_class.{code}: count,
model.model_id, environment.git_commit, finished_at
```

两个硬性 UI 要求：
1. `mode=mock` 必须显著标注"模拟数据"，不得与真实结果同色同权重；
2. 页面**不显示准确率**，只显示请求成功率与错误分布，正确率由人工复核后另行发布。
